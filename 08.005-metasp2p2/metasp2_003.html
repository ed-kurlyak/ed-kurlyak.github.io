Эта команда ниже запускает THC Hydra — программу для перебора логинов и паролей (brute force). В данном случае она пытается подобрать пароль для пользователя admin на учебном веб-приложении DVWA (Damn Vulnerable Web Application).

Разберем команду по частям. 


hydra -V -l admin -P /usr/share/wordlists/rockyou.txt 10.0.2.3 http-get-form "/dvwa/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:H=Cookie:PHPSESSID=023d51270ddc266b8719c2c40820602e;security=low:F=Username and/or password incorrect."

1)hydra

Это имя программы.

Hydra умеет подбирать пароли к огромному количеству сервисов:

HTTP
HTTPS
FTP
SSH
Telnet
SMB
MySQL
PostgreSQL
RDP
SMTP

и многим другим.

2) -V

-V

Большая буква V означает

Verbose.

Hydra будет выводить каждую попытку.

Например

[ATTEMPT] admin : 123456
[ATTEMPT] admin : password
[ATTEMPT] admin : qwerty

Без -V попытки обычно не отображаются.

3) -l admin

Маленькая буква l (не цифра 1).

-l admin

означает использовать один логин

admin

То есть Hydra НЕ перебирает пользователей.

Она перебирает только пароль.

Если бы нужно было перебирать пользователей тоже, используют

-L users.txt

где

users.txt

admin
root
test
john

4) -P

-P /usr/share/wordlists/rockyou.txt

Большая буква P.

Это словарь паролей.

Hydra читает файл

rockyou.txt

например

123456
password
qwerty
admin
letmein
football
...

и по очереди подставляет каждый пароль.

5)

10.0.2.3

IP-адрес сервера.

Именно сюда Hydra отправляет HTTP-запросы.

6)http-get-form

Это один из модулей Hydra.

Он означает:

форма авторизации работает через HTTP GET.

Например браузер может отправлять такой запрос:

GET /login.php?user=admin&pass=1234

или

GET /dvwa/vulnerabilities/brute/?username=admin&password=1234&Login=Login

Если бы использовался метод POST, был бы модуль

http-post-form

7) Вся длинная строка

После http-get-form идет описание формы. 


"/dvwa/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:H=Cookie:PHPSESSID=023d51270ddc266b8719c2c40820602e;security=low:F=Username and/or password incorrect."

Hydra делит её по двоеточиям (:) на несколько частей.

Первая часть

/dvwa/vulnerabilities/brute/

Это URL.

Hydra будет обращаться к

http://10.0.2.3/dvwa/vulnerabilities/brute/

Вторая часть

username=^USER^&password=^PASS^&Login=Login

Это параметры запроса.

Например Hydra подставляет

USER = admin

PASS = 123456

и получается

username=admin
password=123456
Login=Login

Следующая попытка

username=admin
password=password
Login=Login

Потом

username=admin
password=qwerty
Login=Login

и так далее.

Что означает

^USER^

Это специальный маркер Hydra.

Он заменяется текущим логином.

Что означает

^PASS^

Это специальный маркер.

Hydra заменяет его очередным паролем из словаря.

Почему есть

Login=Login

Потому что HTML-форма обычно содержит кнопку: 


<input
type="submit"
name="Login"
value="Login">

Когда пользователь нажимает кнопку, браузер отправляет

Login=Login

Hydra имитирует обычный браузер, поэтому этот параметр тоже передается.

8) H=

Следующая часть

H=Cookie:PHPSESSID=023d51270ddc266b8719c2c40820602e;security=low

H= означает добавить HTTP-заголовок (Header).

В данном случае добавляется заголовок Cookie:

Cookie:
PHPSESSID=023d51270ddc266b8719c2c40820602e;
security=low

Это нужно потому, что DVWA требует активную сессию и установленный уровень безопасности.

PHPSESSID

Это идентификатор сессии PHP.

Например

PHPSESSID=023d51270ddc266b8719c2c40820602e

По нему сервер узнает пользователя.

security=low

DVWA имеет несколько уровней защиты которые мы с вами уже настраивали на странице DVWA.

low
medium
high
impossible

Cookie

security=low

говорит серверу

использовать уровень Low

На этом уровне защита минимальна, и приложение специально предназначено для учебных лабораторий.

9) F=

Последняя часть

F=Username and/or password incorrect.

F= означает строку, указывающую на неудачную попытку входа (Failure), то есть та строка которая пишеться на странице в браузере после неудачного входа.

Hydra после каждого запроса анализирует ответ сервера.

Если видит

Username and/or password incorrect.

значит

пароль неверный

Если этой строки нет, Hydra считает, что вход, вероятно, успешен, и сообщает найденные учетные данные.

Можно так же через символ | сложить несколько фраз, сообщений ответов, тогда будет использоваться операция "или" например ниже:

F=Username and/or password incorrect.|Login failed

Если сервер ответил

Username and/or password incorrect.

или

Login failed

попытка считается неудачной.

Как работает команда целиком

Если представить процесс упрощенно, Hydra делает примерно следующее:

Берет первый пароль из rockyou.txt.
Формирует GET-запрос с логином admin и этим паролем.
Добавляет Cookie с указанной сессией и уровнем безопасности.
Отправляет запрос на страницу /dvwa/vulnerabilities/brute/.
Получает HTML-ответ.
Проверяет, содержится ли в ответе текст Username and/or password incorrect..
Если текст найден — переходит к следующему паролю.
Если текст отсутствует — считает, что пароль найден, и завершает подбор.

Символ : используется в двух разных ролях.

Строка выглядит так: 


/dvwa/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:H=Cookie:PHPSESSID=023d51270ddc266b8719c2c40820602e;security=low:F=Username and/or password incorrect.

Hydra разбирает ее слева направо.

Она ожидает следующий формат:

URL : параметры : дополнительные опции : условие

То есть здесь получается:

1) /dvwa/vulnerabilities/brute/

2) username=^USER^&password=^PASS^&Login=Login

3) H=Cookie:PHPSESSID=023d51270ddc266b8719c2c40820602e;security=low

4) F=Username and/or password incorrect.

Обратите внимание на третью часть.

H=Cookie:PHPSESSID=023d51270ddc266b8719c2c40820602e;security=low

Здесь первое двоеточие (перед H=): 


...Login=Login : H=Cookie...
               ↑

— это разделитель полей Hydra.

А вот второе двоеточие:

H=Cookie:PHPSESSID=...

↑

уже не является разделителем Hydra.

Оно входит в значение параметра H=.

Почему?

Потому что HTTP-заголовок всегда записывается как

Имя: Значение

Например

Host: google.com

или

User-Agent: Mozilla/5.0

или

Cookie: PHPSESSID=...

То есть

Cookie:PHPSESSID=...

— это обычный HTTP-заголовок:

То есть Hydra сформирует HTTP-запрос примерно такого вида:

GET /dvwa/vulnerabilities/brute/?username=admin&password=123456&Login=Login HTTP/1.1
Host: 10.0.2.3
Cookie: PHPSESSID=023d51270ddc266b8719c2c40820602e; security=low

Именно поэтому двоеточие после Cookie — это не разделитель полей Hydra, а обычный синтаксис HTTP-заголовка.

То есть внешние двоеточия разделяют крупные блоки, а двоеточие после Cookie принадлежит уже содержимому третьего блока — HTTP-заголовку. Поэтому Hydra не воспринимает его как начало нового поля.
